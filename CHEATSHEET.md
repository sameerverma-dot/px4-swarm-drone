# Cheat sheet — where things are, and how to push

*The one-page answer to "wait, where is that again?"*
Longer docs: `STACK_README.md` (running) · `SYSTEM_GUIDE.md` (how it works) ·
`NEXT_SESSION.md` (plan) · `PROGRESS.md` (status).

---

## 1. The three folders that matter

```
~/px4_ros_ws        ← YOUR WORK LIVES HERE. This is the git repo.
~/PX4-Autopilot     ← flight firmware + simulator (not yours, but you edit the camera SDF)
~/maps              ← OUTPUTS: flown tracks + geotagged hazards
```

Everything else (`~/Micro-XRCE-DDS-Agent`, `~/Downloads/QGroundControl.AppImage`,
`~/yolo_test`, `~/runs`) is a dependency you rarely open.

## 2. Inside `~/px4_ros_ws` — the paths you actually edit

| What | Path |
|---|---|
| **Survey node** (flight logic) | `src/survey/survey/survey_node.py` |
| **Detector node** (YOLO + geotag) | `src/perception/perception/detector_node.py` |
| Mission launch (survey + detect) | `src/survey/launch/mission.launch.py` |
| Survey-only launch | `src/survey/launch/survey.launch.py` |
| Perception-only launch | `src/perception/launch/perception.launch.py` |
| Offline detector test | `src/perception/test_perception.py` |
| Map renderer | `src/perception/perception/hazard_map.py` |
| System self-test | `check_system.sh` |
| Stack launcher | `start_px4_sim.sh` |
| Camera resolution / frame rate | `~/PX4-Autopilot/Tools/simulation/gz/models/mono_cam/model.sdf` |

**Traps:**

- `~/px4_ros_ws/survey_node.py` (workspace **root**) is a stale standalone copy.
  It is *not* what the package runs. Always edit the one under `src/`.
- `build/`, `install/`, `log/` are generated by colcon. Never edit, never commit.
- `src/px4_msgs/` and `src/px4_ros_com/` are vendored dependencies, gitignored.

## 3. Outputs — `~/maps`

| File | What |
|---|---|
| `survey_track_<unix_ts>.csv` | `t_s, x_ned, y_ned, z_ned` — the flown path |
| `hazard_points.csv` | `t_s, x_ned_north, y_ned_east, class, conf, alt_m` — detections |
| `hazard_map_<ts>.png` | the rendered map — the actual deliverable |
| `hazard_map_<ts>.geojson` | same points in WGS84, for QGIS / Google Earth |

`hazard_points.csv` **appends across runs**. Move it aside before a fresh flight
or you'll be comparing two flights mixed together.

## 4. The three commands you need every time

```bash
# 1. boot the sim (normal terminal, NOT inside tmux)
bash ~/px4_ros_ws/start_px4_sim.sh gz_x500_mono_cam_down

# 2. what's actually working? PASS/FAIL per layer
bash ~/px4_ros_ws/check_system.sh

# 3. build + fly
cd ~/px4_ros_ws
colcon build --packages-select survey perception && source install/setup.bash
ros2 launch survey mission.launch.py x_max:=30.0 y_max:=20.0 altitude:=5.0

# 4. render the map
ros2 run perception hazard_map --area 0,30,0,20 --truth 10,15
```

Stop everything: `tmux kill-server`

## 5. Pushing to GitHub

Repo: **`github.com/sameerverma-dot/px4-swarm-drone`**, remote `origin`, branch `main`.

### Safety first

Your PAT lives in `~/.git-credentials`. That is in your **home** folder, not in
the repo, so `git add` inside `~/px4_ros_ws` cannot pick it up. Two rules:

- Never move or copy that file into `~/px4_ros_ws`.
- **Always run `git status` and read the file list before committing.** If you
  ever see `.git-credentials`, a `.env`, or anything with a token in the list,
  stop and remove it from staging (`git restore --staged <file>`).

### The normal flow

```bash
cd ~/px4_ros_ws

git status                 # ← read this. Every time.
git add -A
git commit -m "your message"
git push origin main
```

### Safer flow — branch first (recommended for bigger changes)

```bash
cd ~/px4_ros_ws
git checkout -b fix/geotag-latency

git status
git add -A
git commit -m "your message"
git push -u origin fix/geotag-latency
```

Then open a pull request on GitHub and merge it there. This keeps `main` always
working, which matters once the swarm work starts breaking things.

To come back to main afterwards: `git checkout main && git pull`.

### Useful checks

```bash
git log --oneline -10          # recent history
git diff                       # unstaged changes
git diff --stat HEAD           # what a commit would include, summarised
git branch --show-current      # which branch am I on
git remote -v                  # where does origin point
```

### If push is rejected

```bash
git pull --rebase origin main   # replay your commits on top of remote
git push origin main
```

Never `git push --force` to `main`.
